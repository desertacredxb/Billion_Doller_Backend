# BDFX private client reporting

The existing operations assistant can read per-account operational history and MT5 state for verified BDFX clients with LIVE CLIENT accounts. It can list account references to resolve ambiguous identities, then read registration/KYC status, live balance/equity, open positions, MT5 deal history, stored deposit requests and stored withdrawal requests. Each history is limited to ten records per page, with at most three source calls per AI question and pages 1–999. This is not an unrestricted database query or a bulk export.

The authenticated n8n workflow supplies `accessContext` only after its existing native Telegram group identity and getChatMember checks. The role and timestamp come from that native response, never the message text. Only a fresh creator/administrator context enables private tools. Existing member-level fixed reports remain unchanged. The dedicated business-report credential is a trusted service boundary; anyone allowed to edit the workflow or use that credential must be treated as an operator. Production execution payload logging stays disabled.

Every remote MT5 read first resolves a BDFX-owned live client account and verified user with explicit inclusion projections. Account passwords, identity documents, contacts, bank/wallet details, settlement tokens and provider raw payloads never enter the AI tool output. Existing MT5 host, manager credentials and connection behavior remain unchanged. The reporting facade permits exact authentication and read endpoint paths, including a deny-by-default check because the legacy API has mutating GET methods. It adds bounded timeouts and destroys its own agent after use; it does not modify the existing trading, balance, payment or registration handlers.

Live values are labeled as MT5 state at check time, with the currency recorded on the BDFX account. Missing values remain unavailable. Provider count/page calls are sequential snapshots; MT5 history order is not promised to be newest first. Raw volume is in MT5 units. Deposit orders without an original currency retain that uncertainty, separately from recorded credited USD. Request status is not independent bank settlement evidence. A profile is not a full transaction history; request/deal pages disclose their exact coverage.

Non-admins, stale role contexts, foreign/unknown accounts, mismatched MT5 logins, provider errors and malformed results fail closed. No payment, trade, KYC approval, password or customer mutation is available through these tools. The daily report schedule and other-company integrations are unchanged.

The website analytics public-path allowlist includes the new India, Pakistan and Vietnam country-learning routes, preserving the existing owner-only analytics API and visitor consent requirements. It does not make detailed customer reporting public.

Validation includes the existing backend suite plus native-role provenance, account ownership, safe projections, mixed-currency handling, fixed read paths, timeouts, pagination, missing-data behavior and the AI tool authorization boundary. Live connection checks should output only boolean/schema evidence, not customer financial values or credential data.
